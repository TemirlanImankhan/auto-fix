# AutoFix AI — дипломный проект

Веб-прототип системы предварительной классификации возможных неисправностей автомобиля по характеристикам и симптомам. Проект предназначен для исследования и демонстрации методов классификации; он не заменяет OBD-II-сканер, осмотр и заключение специалиста.

## Возможности

- локальная диагностика с моделями Logistic Regression, Decision Tree, Random Forest и системой правил;
- сравнение моделей по Accuracy, Precision, Recall и macro F1;
- регистрация и вход по email/паролю;
- приватный гараж и история прогнозов в PostgreSQL, разделённые по аккаунтам;
- журнал обслуживания с планированием следующей даты или пробега для каждого автомобиля;
- объяснение результата по фиксированным правилам без внешних AI-сервисов и API-ключей.

## Структура проекта

```text
src/
  components/       общий интерфейс и переиспользуемые компоненты
  routes/           страницы и маршруты приложения
  lib/
    ml/             признаки, синтетическая выборка, алгоритмы и интерпретация
    data.ts         авторизованные функции гаража, истории и обслуживания
    auth/           Better Auth, собственная регистрация email/пароль
    app-data/       платформенные модули шаблона, не используются AutoFix
  styles.css        общие дизайн-токены и базовые стили
docs/
  architecture.md  слои приложения, поток диагностики и границы прототипа
  thesis/           структура пояснительной записки и план доработки исследования
report/             имеющиеся материалы лабораторной работы
```

## Как устроена диагностика

1. Форма собирает характеристики автомобиля и отмеченные симптомы.
2. `src/lib/ml/features.ts` преобразует ввод в числовой вектор признаков.
3. `src/lib/ml/engine.ts` обучает и оценивает модели на воспроизводимой синтетической выборке.
4. Результат, альтернативные классы и оценки моделей рассчитываются на сервере.
5. Приватный результат сохраняется в БД с `user_id` из проверенной сессии.
6. Журнал обслуживания использует отдельную таблицу с составным ограничением, связывающим запись только с автомобилем того же пользователя.
7. `src/lib/ml/explanation.ts` формирует объяснение локально из прогноза и выбранных симптомов.

Подробности и ограничения описаны в [архитектуре](docs/architecture.md). План оформления диплома и список необходимых исследований находятся в [структуре дипломной работы](docs/thesis/README.md).

## Текущие ограничения и следующий этап

Текущая модель пока использует синтетическую выборку и не должна использоваться для реальной диагностики. Для исследовательских выводов нужно подключить документированный набор реальных данных, описать разметку и протокол проверки, затем пересчитать метрики на независимой выборке. Датасет сейчас подбирается; до замены модели интерфейс явно остаётся прототипом.

Приложению не нужен Grok или внешний AI-сервис. Учётные записи, автомобили, история и журнал обслуживания используют Better Auth и миграции PostgreSQL. В workspace есть временный PGLite-режим предпросмотра; постоянная БД на публикации подключается через предусмотренную платформой PostgreSQL/Neon-конфигурацию.
